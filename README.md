# Backrooms Level 0 — フォトリアル

Unity 6 + HDRP + DXR による Backrooms Level 0 の再現。
目標は「現実と見まがうグラフィック作品」。non-VR が主軸で、VR は後からの移植。

## 現在の状態

| 項目 | 内容 |
|---|---|
| エンジン | Unity 6000.5.8f1 / HDRP 17.5 / DirectX 12 固定 |
| GI | レイトレーシング（RTGI フル解像度・2 バウンス・レイ長 20m） |
| 反射 | レイトレーシング反射（フル解像度・スムースネス 0.20 から） |
| 照明 | 蛍光灯トロファーごとのエリアライト 13 灯 + ボリュメトリック |
| ジオメトリ | 25,376 頂点 / 11,676 三角形 |
| 出力 | 1920x1080 |
| **実測** | **平均 379 fps / 最悪フレーム 8.6ms**（RTX 3060） |

目標 60fps に対して 6 倍の余裕がある。品質側にさらに振れる。

外部パッケージは HDRP と uGUI のみ。入力はエンジン組み込みのレガシー入力を使う
（Input System 1.12.0 は Unity 6000.5 で非推奨になった `TreeView` API を使っており
エディタアセンブリがコンパイルできない）。

## フォトリアルのために入れているもの

CG がバレる原因を、影響の大きい順に潰している。

### 1. 全エッジの面取り

実在の建築に数学的な直角は存在しない。塗装は角で盛られて丸まり、石膏ボードの
コーナービードは必ず R を持ち、幅木の角は欠ける。`MeshBuilder.BeveledBox()` が
6 面 + 12 稜線 + 8 隅を生成する。壁 4mm / 幅木 2mm / T バー 1.2mm / 器具枠 1.5mm。

### 2. 実寸に対応した汚れの焼き込み

壁の UV は高さ方向にテクスチャを 1 回だけ張る（`MeshBuilder.UvScaleV`）。
これにより汚れを実際の高さに置ける。

- 幅木際の掃除機とモップの跡（上端が 0.14〜0.32m で波打つ）
- 毛細管現象で吸い上がったシミ
- 台車と靴のこすれ（0.30m 帯）
- 手の皮脂汚れ（1.18m 帯）
- 空調由来の天井際の煤
- 上から垂れた雨染み

汚れた箇所は AO とスムースネスも同時に落としている。

**制約: ベーステクスチャに入れてよい特徴サイズはタイル 1 辺の 1/8 まで。**
これを破ると 2.12m のタイル周期が暗い弧の繰り返しとして見える（一度踏んだ）。
大スケールの変調は 11m 周期のディテールマップ側の役割。
ノイズは FFT ローパス方式で作っており、数学的に完全に周期的なので継ぎ目が出ない。

### 3. 個体差

- **天井タイル**: 座り高さ ±1.5mm、四隅の傾き、中央の垂れ 1.2〜4.7mm、
  4% が押し上がり 5% が落ちかけ。2x2 に分割して中央を垂れさせている。
- **タイルの絵柄**: 6x6 アトラスからランダムに引き、さらに UV の向きを 8 通りから
  選ぶので実質 288 通り。雨漏りのシミ 5 枚・交換された白いタイル 2 枚・
  黄ばんだタイル 3 枚を仕込んである。
- **カーペット**: 動線の摩耗・染み・毛並みムラの 3 層を 9m 周期で重ねる。

### 4. 建築設備

設備が一切無い空間は、材質をどれだけ詰めても「人が使っていた場所」に見えない。

- スプリンクラー 8 基（落とし配管・デフレクタ板・感熱体、真鍮）
- 煙感知器 3 基
- 空調吹出口 3 基（600 角 4 方向ルーバを 4 段の同心リングで）
- コンセント 4 口（床上 300mm、2 口）

### 5. 物理的なカメラ

演出的な色調整は一切しない。実在のカメラとレンズが持つ性質だけを再現する。

- ACES トーンマップ、TAA (High)
- 35mm 相当の 38 度画角（ゲーム的な広角より写真に近い）
- 色収差 0.055 / 周辺光量落ち 0.13 / ブルーム 0.13
- コントラスト・彩度・ホワイトバランスは全てゼロ。
  4200K の蛍光灯の下でカメラが見る色をそのまま出す

## 実行方法

```powershell
.	oolsackrooms.ps1 materials   # マテリアルを作り直す
.	oolsackrooms.ps1 scene       # シーンを作り直す
.	oolsackrooms.ps1 capture     # 再生してスチルと fps を採取
```

エディタで触る場合は `BackroomsRT` を開いて
`Assets/_Project/Scenes/Level0.unity` を再生する。
メニューバーの `Backrooms` から各ステップを個別に実行できる。

DXR はグラフィックスデバイスを要するため、`capture` だけは `-batchmode` を使わない。

| キー | 動作 |
|---|---|
| WASD | 移動 |
| Shift | 走る |
| Ctrl / C | しゃがむ |
| F | 手持ちライト |
| Esc | ポインタ解放（クリックで再ロック） |

## 構成

```
backroom2/
├─ tools/backrooms.ps1              ビルド・キャプチャの実行
├─ docs-VR-port.md                  VR 移植の手順と既知の落とし穴
├─ artifacts/                       ログ・レポート・スチル
└─ BackroomsRT/Assets/_Project/
    ├─ Art/Textures/                CC0 素材と生成マップ（CREDITS.md 参照）
    ├─ Art/Materials/               コード生成された HDRP マテリアル
    ├─ Scenes/Level0.unity
    ├─ Settings/Level0_Volume.asset ボリュームプロファイル
    └─ Scripts/
        ├─ Generation/  MeshKit / Level0Builder   実寸ジオメトリと設備
        ├─ Player/      FirstPersonController / Flashlight
        ├─ Capture/     FlatCaptureRunner
        └─ Editor/      Setup / MaterialBuilder / SceneBuilder / CaptureTool
```

シーンとマテリアルは全てコードから生成される。手作業でエディタを触る必要はなく、
`toolsackrooms.ps1` を回せばいつでも同じ状態を作り直せる。

## 次に効きそうなこと

現状で残っている「作られた場所」感の原因を、影響の大きい順に。

1. **物が何も無い**。人が使っていた痕跡（放置された椅子、段ボール、コード、
   ゴミ、非常口サイン）が一切ない。
2. **建築の個体差が無い**。全ての壁が同じ壁紙、全ての床が同じカーペット。
   補修跡、張り替えた区画、色の違う増築部分などが無い。
3. **照明が均一すぎる**。器具ごとの色温度のばらつき、切れかけのちらつき、
   安定器の唸りに同期した明滅。
4. **カーペットが遠景で均質**。壁際の汚れの蓄積は世界座標が要るので、
   デカールか頂点カラーの導入が必要。
5. ベイクしたライトマップへの移行（VR 移植の前提でもある）。
